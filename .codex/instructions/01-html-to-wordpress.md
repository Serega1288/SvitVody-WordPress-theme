# Частина 1. Інтеграція HTML-верстки у WordPress

## Загальні правила

- Відповідай українською мовою, якщо користувач не просить інакше.
- Перед змінами перевіряй структуру проєкту і поточні файли.
- Це інструкції для майбутніх задач. Якщо користувач просить тільки записати або оновити інструкції, не виконувати саму інтеграцію.

## Середовище

- Проєкт працює через Docker.
- Вважати, що Docker уже піднятий і запущений, якщо користувач не повідомив інше.
- Для перевірок використовувати Docker-оточення проєкту, коли це потрібно для PHP або WordPress.

## Робота зі старими файлами

- Старі папки та файли не видаляти одразу.
- Якщо потрібно замінити або використати стару папку чи файл, переносити їх у папку `old`.
- Старі файли та папки переносити в `old` без перейменування і без додавання приставок до назв.
- Не перезаписувати важливі файли без попередньої перевірки їхнього вмісту.

## Інтеграція HTML-верстки у WordPress

- Поточна HTML-верстка знаходиться у папці `html`.
- Проєкт знаходиться у `www-svitvody`, також враховувати шлях `html\`, якщо він використовується в структурі задачі.
- Потрібно інтегрувати наявну HTML-верстку у WordPress-проєкт.

## Базові налаштування WordPress

- Перед створенням головної сторінки потрібно перевірити, чи вона вже існує в WordPress.
- Якщо потрібна сторінка вже створена, не створювати дубль, а використати наявну сторінку.
- Після створення головної сторінки потрібно перевести WordPress у режим статичної головної сторінки.
- У `Налаштування -> Читання` вибрати `Статичну сторінку`.
- Для поля `Домашня сторінка` вибрати сторінку `Головна`.
- Для поля `Сторінка записів` залишити значення `— Обрати —`, якщо користувач не просив окрему сторінку блогу.
- У `Налаштування -> Постійні посилання` встановити користувацьку структуру `/%category%/%postname%/`.
- Після зміни структури постійних посилань потрібно оновити rewrite rules WordPress.

## Assets

- Папку `assets` з верстки перенести у таку саму папку проєкту.
- Стару папку `assets` у проєкті не видаляти, а перенести в папку `old` без перейменування.
- Після перенесення перевірити шляхи до CSS, JS, зображень, шрифтів та інших ресурсів.

## Стилі та скрипти

- CSS і JS з HTML-верстки можна інтегрувати через WordPress-файл `inc/enqueue.php`, якщо це потрібно для коректної роботи теми.
- Стилі з HTML-верстки мають підключатися як окремі CSS-файли через `wp_enqueue_style()`.
- Скрипти з HTML-верстки мають підключатися як окремі JS-файли через `wp_enqueue_script()`.
- У `header.php` залишати `wp_head();`, щоб WordPress виводив підключені стилі в зоні `head`.
- У `footer.php` залишати `wp_footer();`, щоб WordPress виводив підключені скрипти внизу сторінки перед закриттям `body`.
- Не переносити вручну всі `<link rel="stylesheet">` і `<script>` з HTML у `header.php` або `footer.php`, якщо вони вже підключені через `enqueue.php`.

## Розподіл HTML-коду між PHP-файлами

- `header.php` використовувати для початку HTML-документа.
- У `header.php` мають бути `<!doctype>`, тег `html`, `head`, відкриття `body`, а також верхня частина сторінки до місця, де починаються блоки змінного контенту.
- `footer.php` використовувати для нижньої частини сторінки, закриття основних wrapper-блоків, footer-секції, а також закриття `body` і `html`.
- Усі інші блоки зі сторінок HTML-верстки, які використовуються як змінний контент, переносити в один `index.php`.
- Приховані блоки, які повторюються на сторінках верстки, переносити до `header.php` або `footer.php` залежно від того, де вони ближче розташовані у вихідному HTML-коді.
- Потрібно акуратно розподілити всі відкриті та закриті HTML-теги між `header.php`, `index.php` і `footer.php`, щоб структура DOM залишалась валідною.
- Файли мають підключатися між собою за стандартом WordPress:
  - в `index.php` використовувати `get_header();`
  - в `index.php` використовувати `get_footer();`
  - у `header.php` має бути `wp_head();`
  - у `footer.php` має бути `wp_footer();`

## Приховані та повторювані блоки

- Приховані блоки, які повторюються на сторінках і розташовані у верхній частині HTML-коду біля header, переносити в `header.php`.
- Якщо прихований повторюваний блок розташований ближче до footer або перед закриттям `body`, переносити його в `footer.php`.
- Якщо блок є частиною змінного контенту конкретної сторінки, переносити його в `index.php`.
- Це правило належить до першого етапу структурування HTML-верстки між `header.php`, `index.php` і `footer.php`.

## Обережність

- Не робити зайвих рефакторингів.
- Не видаляти файли без прямого прохання.
- Не робити commit без окремого прохання користувача.
