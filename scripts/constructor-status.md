# Стан інтеграції конструктора

## Реалізовано

- Шаблон `project-theme/page-constructor.php`, диспетчер `inc/box-constructor.php` і 9 layouts ACF Flexible Content.
- Головний банер, внутрішній банер, акції та пропозиції, наша вода, склад води, переваги для дому, вода для організацій, вартість води, як ми працюємо.
- Сторінки `7/41`, `8/43`, `9/45`, `10/47` наповнено українською та російською за набором секцій відповідних HTML-сторінок. Використано наявні сторінки й мовні зв'язки.
- Група ACF `Конструктор сторінки` видима в адмінці; звичайний редактор прихований для шаблону Constructor.
- Через ACF зареєстровано `sv_product` (Товари) і `sv_product_category` (Категорії товарів) із вимкненими публічними сторінками та архівами.
- Імпорт є окремою CLI-операцією: на звичайних запитах визначення полів і значення з бази не перезаписуються.

## Додаткові товари та послуги

- Користувач погодив автоматичний вивід товарів з `sv_product` у всіх блоках `Додаткові товари та послуги`.
- Спільна вибірка `inc/products.php` повертає опубліковані товари поточною мовою для карток і кошика; у додаткових товарах показує лише тип `extra`, воду з тарифами відокремлено. Заголовки самого блоку залишаються в конструкторі сторінки.
- Категорії нормалізовано до двох логічних груп із перекладами Polylang: `Аксесуари / Аксессуары` для всіх додаткових товарів, включно із заставним бутлем, та `Вода / Вода` для основного товару. Кожен товар має рівно одну категорію; окремі категорії `Тара` видалено.
- Створені товари `Застава за бутель` (735/736) та `Помпа ECONOM PLUS` (738/739), українські й російські переклади та мовні зв'язки Polylang. Публічні URL залишаються вимкненими.
- Група ACF `Дані товару` доступна в адмінці: підпис, текст кнопки, ціна, валюта, зображення й alt. Назва береться із заголовка запису. Нові опубліковані товари з'являються автоматично.
- Тексти інтерфейсу кошика та форми попапу не додавати до ACF для перекладу згідно з окремим рішенням користувача.

## Сповіщення про заявки

- Додано вкладку `Сповіщення заявок` на сторінці `theme-settings`: Email одержувача, перемикачі каналів, Telegram-токен, Chat ID, ID теми та видалення токена. Значення спільні для мов; редагування лише адміністратором, токен не повертається в HTML.
- `inc/order-notifications.php` підключений після `inc/orders.php`: черга WP-Cron після збереження заявки, Email через `wp_mail()`, Telegram через `sendMessage`, стани каналів і повтор ненадісланих. Успішні канали не повторюються; непідтверджена доставка потребує ручної перевірки.
- Власні SMTP-поля та код налаштування транспорту прибрані за уточненням користувача. Поштовий плагін користувач встановить самостійно.
- Реальні повідомлення не надсилалися. До уточнення користувача перевірено обробники лише з підмінними транспортами; після уточнення перевіряються тільки опції та синтаксис. Реальна доставка поки не перевірена.
- Міграція полів: `inc/migrations/constructor/order-notifications.php`; read-only перевірка адмінки: `scripts/notification-options-check.cjs`. Резервні копії: `project-theme/old/06-notifications/`, `database/before-notifications.sql`.
- Після окремого дозволу користувача виконано один реальний Telegram-тест (заявка 801, пошта для неї вимкнена). Telegram повернув HTTP 401: токен не авторизований. Потрібна заміна токена в адмінці; реальна доставка не підтверджена. Тестова заявка видаляється після діагностики.
- Для локального Docker виправлено loopback WP-Cron: серверний запит до `localhost:8080/wp-cron.php` спрямовується на внутрішній Apache `127.0.0.1:80`, збережено Host. Публічні URL та продакшн-домени не змінюються. Потрібна фінальна перевірка автоматичної Telegram-доставки після виправлення токена.
- За відповіддю користувача поштовий перемикач залишено увімкненим. Тестове надсилання пошти не запускати. Існуючу заявку 786 не надсилали вручну; вона залишається у звичайній черзі.

## Повторний запуск міграцій

З кореня проєкту:

```powershell
docker compose run --rm --entrypoint wp wpcli --allow-root --user=dev eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/import.php schema
docker compose run --rm --entrypoint wp wpcli --allow-root --user=dev eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/import.php content
docker compose run --rm --entrypoint wp wpcli --allow-root eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/check.php verify
docker compose run --rm --entrypoint wp wpcli --allow-root eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/products.php languages
docker compose run --rm --entrypoint wp wpcli --allow-root --user=dev eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/products.php content
docker compose run --rm --entrypoint wp wpcli --allow-root --user=dev eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/product-cart.php
docker compose run --rm --entrypoint wp wpcli --allow-root --user=dev eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/water-product.php
docker compose run --rm --entrypoint wp wpcli --allow-root --user=dev eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/product-categories.php
docker compose run --rm --entrypoint wp wpcli --allow-root eval-file /var/www/html/wp-content/themes/project-theme/inc/migrations/constructor/check-products.php verify
```

Існуючі визначення та наявний конструктор на сторінці зберігаються, включно з навмисно порожнім конструктором. Для зміни схеми застосовувати окрему точкову міграцію після читання поточних даних, а не видаляти групу й створювати її заново.

## Перевірки та резервні копії

- Вода: товари 753/754 (uk/ru), цінові рівні 2/6/12 з цінами 180/170/160 грн. Усі наявні мовні сторінки цінового блоку використовують `water_product`; тарифи редагуються в товарі, не в конструкторі сторінки. Старі значення сторінок залишено в метаданих і резервній копії, старе поле приховано шляхом видалення його визначення ACF.
- Заявки: непублічний `sv_order`, тільки адміністратор, контакти й доставка, незмінний знімок товарів/тарифів/суми, стан обробки. Обробник у `inc/orders.php` перевіряє кошик і ціни на сервері; повторні запити з одним ключем не дублюють заявку.
- Перевірки заявки та тарифів: `scripts/orders-water-check.cjs`, `scripts/water-product-admin-check.cjs`, `inc/migrations/constructor/check-orders.php`. Скриншоти: `audit-screenshots/orders-water/`. Перед змінами: `project-theme/old/05-orders-water/` і `database/before-orders-water.sql`.
- Перевірено тарифи на кількостях 2/5/6/11/12/20, вибраний рівень на картках, реальне збереження заявки uk/ru на desktop/mobile, стан в адмінці, відмову при підміні суми/невалідних полях/кількостях, приватні URL, повторний і одночасний запит. При тестовій помилці сервера форма та кошик збереглися. Зміна тарифу через ACF відобразилася у блоках та каталозі кошика; початкову ціну повернуто. Тестові заявки 756-760, 767-768 видалені.

- PHP і JavaScript пройшли перевірку синтаксису.
- Перевірено 8 сторінок на ширині 1440 і 390: HTTP 200, відсутність JS-помилок, зламаних зображень, дубльованих ID та горизонтального переповнення сторінки.
- В адмінці перевірено збереження тестової сторінки; у браузері перевірено порядок, вимкнення секції, повторення layouts, незалежні слайдери й порожній конструктор.
- Перевірено відкриття попапу з цінового блока; ціни й кількість з конструктора передаються в наявну логіку кошика.
- Тип товарів і категорії не включені до наборів публічних sitemap. Прямі запити не розкривають тестовий товар; тимчасові записи для перевірки видалені.
- Скриншоти та результати перевірок: `audit-screenshots/constructor/`.
- Початкові файли: `project-theme/old/04-page-constructor/`, назви файлів збережені.
- Знімок бази перед інтеграцією: `database/before-constructor.sql`.
- Перед підключенням товарів: `project-theme/old/04-products/` і `database/before-constructor-products.sql`.
- Перевірка товарів: `scripts/constructor-products-check.cjs`; результати й скриншоти у `audit-screenshots/constructor-products/`.
- Перевірено 6 мовних сторінок на ширинах 1440/390, спочатку з двома товарами, потім із третім тимчасовим: автоматичний вивід, завантаження зображень, додавання в кошик та сума з дробовою ціною. JS-помилок і горизонтального переповнення немає. Тимчасові товари 740/741 видалені.
- В адмінці перевірено поля товару, медіа, категорії, переклади та видимість групи `Дані товару` в ACF. Повторний імпорт зберіг існуючі товари без дублів; публічні URL товару й категорії та запит `?post_type=sv_product&p=735` повернули 404.
- Додано окремий `product_cart_description` у групу `Дані товару`, з Message `Мінікошик`; початкові описи заповнено uk/ru. Міграція `product-cart.php` не перезаписує існуючі поля та значення. Резервні копії: `project-theme/old/04-product-cart/`, `database/before-product-cart.sql`.
- `scripts/product-minicart-check.cjs`: перевірено додавання з картки та списку супутніх товарів, збільшення/зменшення кількості, суму, лічильник, збереження після переходу на іншу сторінку й видалення. Обидві мови, desktop/mobile, без JS-помилок; поля товару перевірені в адмінці.
